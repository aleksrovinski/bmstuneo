# План: облачные push-уведомления в BMSTU neo

## Зачем

Локальные уведомления срабатывают, только если приложение недавно запускалось и успело
обновить данные. Студенту нужно узнавать о событиях, даже когда приложение закрыто
неделями: пару перенесли, на завтра поменялась аудитория, выставили баллы за модуль,
через день сдавать ДЗ.

## Главное ограничение

У ЛКС МГТУ нет своих push-уведомлений и нет API для сторонних серверов. Значит, данные
должен опрашивать кто-то из нас. При этом:

- **сервер не должен знать пароль студента.** Хранить учётные данные единой учётной записи
  МГТУ на своём сервере — риск утечки и нарушение того, что обещает
  [политика конфиденциальности](../PRIVACY_POLICY.md): «никаких сторонних бэкендов».
  Это обещание придётся уточнить в любом случае (см. «Приватность»), но пароли на сервер
  не уходят никогда;
- **личные данные (БРС, ФКиС, сессия) доступны только с сессией студента**, то есть только
  на его устройстве;
- **публичные данные доступны без входа**: расписание группы
  (`GET /lks-back/api/v1/schedules/groups/{uuid}/public`), текущая неделя
  (`/schedules/current`), структура университета (`/structure`).

## Архитектура: гибридная схема

| Что | Кто проверяет | Как доставляется |
|---|---|---|
| Изменения расписания группы (перенос, отмена, аудитория, новая пара) | **сервер**, по публичному API | обычный push с текстом |
| Пары на завтра / первая пара утром | **сервер** (расписание известно) | обычный push по расписанию |
| Дедлайны ДЗ/ЛР/РК, новые баллы, ФКиС, результаты сессии | **устройство**, со своей сессией | сервер шлёт «тихий» push → приложение просыпается, обновляет данные и само показывает уведомление |

### Поток 1. Расписание (без личных данных)

1. Приложение при включении уведомлений регистрирует устройство:
   `POST /v1/devices {token, platform, groupUuid, prefs}`. Только токен push, UUID группы
   и настройки — ни имени, ни логина.
2. Планировщик раз в 15–30 минут для **каждой группы, у которой есть подписчики** (а не для
   каждого студента) берёт публичное расписание, сравнивает с прошлым снимком и считает дифф.
3. На дифф уходит push всем подписчикам группы: «Завтра „Теоретическая механика“
   перенесена в 220л (УЛК)».
4. Вечером (по умолчанию 20:00, настраивается) — «Завтра 3 пары, первая в 10:15».

Нагрузка на ЛКС растёт с числом групп, а не студентов: 3 400 групп максимум, реально —
сотни. При 20-минутном интервале это несколько запросов в секунду в пике; нужно
согласовать с владельцами ЛКС или ограничить частоту.

### Поток 2. Личные данные («тихий» push + обновление на устройстве)

1. Сервер раз в несколько часов (и перед дедлайнами по известной сетке недель) шлёт
   устройствам «тихий» push (`content-available: 1` на iOS, data-message на Android) без текста.
2. Приложение в фоне (iOS ~30 с, Android WorkManager) обновляет БРС/ФКиС/сессию через уже
   сохранённую сессию ЛКС, сравнивает с кешем и **само** показывает локальное уведомление:
   «Выставлены баллы: Модуль 1 по „Инженерной графике“ — 27 из 33», «ДЗ-2 по „Сопромату“
   сдать на этой неделе». Ручные отметки «Сдано» учитываются — напоминаний о сданном не будет.
3. Сервер ничего не узнаёт о содержимом.

Ограничения потока 2: iOS не гарантирует доставку тихих push (бюджет системы, режим
энергосбережения, приложение смахнуто из многозадачности). Поэтому критичные напоминания
о дедлайнах дополнительно планируются локально при каждом обновлении данных.

## Технологии

| Компонент | Выбор | Почему / альтернативы |
|---|---|---|
| iOS-доставка | **APNs напрямую** (token-based auth, ключ .p8) | без лишнего посредника; FCM на iOS всё равно работает через APNs |
| Android-доставка | **FCM** + **RuStore Push** как второй канал | FCM в России работает, но не на устройствах без Google-сервисов (Huawei, часть российских прошивок); RuStore Push покрывает их |
| Flutter | `firebase_messaging` (FCM), `flutter_rustore_push`, нативный APNs-токен через уже существующий `AppDelegate` | `flutter_local_notifications` — для локальной части |
| Бэкенд | небольшой сервис (Dart/Go/Node) в **Yandex Cloud** (Serverless Containers + Managed PostgreSQL или YDB) | данные в РФ (152-ФЗ), оплата в рублях; альтернатива — один VPS |
| Планировщик | Yandex Cloud Functions по таймеру / cron на VPS | |

### Данные на сервере (минимум)

```
devices(id, platform, push_token, group_uuid, prefs_json, created_at, last_seen_at)
schedule_snapshots(group_uuid, hash, payload_json, fetched_at)
```

Никаких ФИО, логинов, номеров зачёток, оценок. Токен удаляется при выходе из аккаунта,
отписке и при ответе push-сервиса «токен недействителен».

### API сервера

- `POST /v1/devices` — регистрация/обновление токена, группы, настроек.
- `DELETE /v1/devices/{id}` — отписка (выход, отключение уведомлений).
- `GET /v1/health` — для мониторинга.

Защита: подпись запросов ключом установки (генерируется на устройстве), rate limit по IP,
только HTTPS.

## Настройки в приложении

Экран «Уведомления» в профиле:
- изменения расписания — вкл/выкл;
- «пары на завтра» — вкл/выкл и время;
- дедлайны — за сколько дней напоминать (1/2/3);
- новые баллы БРС и ФКиС — вкл/выкл;
- «тихие часы» (по умолчанию 23:00–8:00).

Запрос разрешения на уведомления — не при первом запуске, а когда студент сам включает
уведомление (Apple отклоняет приложения, которые просят разрешение без объяснения).

## Приватность и публикация

- [Политика конфиденциальности](../PRIVACY_POLICY.md) уже описывает сервер и хранимые данные;
  после развёртывания добавить страну размещения сервера.
- App Store: включить capability Push Notifications (`aps-environment` в entitlements),
  Background Modes → Remote notifications; в анкете App Privacy указать «Device ID» —
  не связан с личностью, не используется для трекинга.
- Google Play: раздел Data safety — то же самое.
- Получить согласие/уведомить администрацию ЛКС о регулярном опросе публичного API.

## Риски

- **ЛКС ограничит или заблокирует опрос.** Смягчение: опрос по группам, кеш, разумный
  интервал, User-Agent с контактом, согласование заранее.
- **Тихие push на iOS не доходят.** Смягчение: дублирующие локальные напоминания о
  дедлайнах, обновление при каждом открытии приложения.
- **Сессия ЛКС истекает в фоне.** Повторный вход в фоне работает (пароль в Keychain), но
  если пароль сменили — уведомления о личных данных молча перестанут приходить. Нужно
  показывать локальное уведомление «Войдите снова, чтобы получать уведомления о баллах».
- **Стоимость.** При тысячах устройств — сотни рублей в месяц (serverless + маленькая БД);
  push-сервисы бесплатны.
